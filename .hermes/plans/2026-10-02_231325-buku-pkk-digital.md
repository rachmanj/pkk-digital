# Buku PKK Digital — Implementation Plan

> **For Hermes:** jalankan lewat `implement`/`subagent-driven-development` per task, satu fase per pass. Fase 0–1 dulu; jangan lompat ke fase 2+ sebelum Fase 1 diterima Iwan.

**Goal:** Menggantikan buku administrasi manual TP PKK Kelurahan (file `Buku PKK GSI new.xlsx`, 23 sheet) dengan satu aplikasi web: input sekali di database orang + kegiatan, lalu semua buku terisi otomatis dan bisa dicetak/disalin ke format buku standar.

**Arsitektur:** Laravel + Blade + AdminLTE (satu app, multi-kelurahan sejak awal lewat `kelurahan_id` di semua tabel; GSI sebagai data pertama). MySQL. Satu entitas kegiatan + presensi menjadi sumber tiga buku sekaligus (DAFTAR HADIR, BUKU KEGIATAN, NOTULEN) — bukan tiga tabel terpisah. Cetak PDF per buku dan export Excel per buku memakai urutan kolom PERSIS seperti file asli.

**Tech Stack:** Laravel 11/12, Blade + AdminLTE, MySQL 8, spatie/laravel-permission, spatie/laravel-activitylog, maatwebsite/excel (export), dompdf (cetak PDF), Docker untuk deploy. Repo: `/home/deahermes/pkk-digital`.

## 2. Model data (Fase 1)

Semua tabel ber-`kelurahan_id` (kecuali tabel murni Laravel). Nomor urut buku (NO. pada tiap buku) **dihitung dari query per tahun**, bukan kolom manual — supaya tidak ada nomor dobel seperti file sekarang.

```
kelurahan(id, nama, kecamatan, kota, provinsi, kode, is_active)
users(id, name, email, password, kelurahan_id, orang_id nullable)   # + spatie roles
pokja(id, kelurahan_id, kode ENUM('I','II','III','IV'), nama)
rt(id, kelurahan_id, nomor, dasawisma, ketua_orang_id nullable)
orang(id, kelurahan_id, nama, jenis_kelamin ENUM('L','P'), tempat_lahir, tanggal_lahir,
      status_perkawinan, alamat, rt_id nullable, pendidikan, pekerjaan, no_hp, foto_path, catatan)
keanggotaan(id, orang_id, kelurahan_id, jenis ENUM('tp_pkk','kader_umum','kader_khusus'),
      pokja_id nullable, jabatan, no_registrasi, sk_nomor, mulai, selesai, is_aktif)
agenda_surat(id, kelurahan_id, jenis ENUM('masuk','keluar'), no_urut_tahun, tanggal_surat,
      tanggal_terima nullable, no_surat, dari, kepada, perihal, lampiran, tembusan,
      pokja_id nullable, file_path nullable, catatan)
disposisi(id, agenda_surat_id, pokja_id nullable, user_id nullable, instruksi,
      status ENUM('baru','proses','selesai'), tenggat, selesai_at, oleh_user_id)
kegiatan(id, kelurahan_id, pokja_id nullable, rt_id nullable, nama, jenis, tanggal,
      jam_mulai, jam_selesai, tempat, acara, uraian, pimpinan_rapat_id nullable)
presensi(id, kegiatan_id, orang_id nullable, nama_manual, alamat_manual, jabatan_manual,
      urut, hadir boolean default true, keterangan, oleh_user_id)
buku_tamu(id, kelurahan_id, pokja_id, tanggal, nama_tamu, alamat, keperluan, tujuan, keterangan)
buku_kunjungan(id, kelurahan_id, tanggal, orang_id nullable, nama, jabatan, lokasi_kunjungan,
      jenis_kegiatan, keterangan)
notulen(id, kegiatan_id unique, macam_rapat, jumlah_diundang, jumlah_hadir, jumlah_tidak_hadir,
      uraian_jalannya, keputusan, lain_lain, penutup, pembuat_id, tempat_tanggal_ttd)
```

Keputusan desain penting:

- **BUKU KEGIATAN & DAFTAR HADIR tidak punya tabel sendiri.** Keduanya *view cetak* dari `kegiatan` + `presensi`. Satu input, tiga buku (hadir, kegiatan, notulen). Ini yang membedakan app dari Excel.
- **Umur tidak disimpan.** Dihitung dari `tanggal_lahir` saat cetak/tampil (file lama menulis "01 Mei 1991/35th" manual dan sudah tidak akurat tahun ini).
- **Peserta presensi** boleh orang dari master (`orang_id`) atau nama manual (`nama_manual`) — di kegiatan RT sering tamu/pihak luar yang belum jadi anggota.
- **Foto** anggota: `orang.foto_path` (file upload), dicetak di daftar anggota kalau ada.

## 7. Risiko, tradeoff, dan pertanyaan terbuka

**Risiko**

- **Data pribadi.** Nama, alamat, tanggal lahir, no. HP, dan foto anggota = data pribadi. Wajib: akses ber-role, tidak ada halaman publik, file foto disimpan di luar `public/` dan disajikan lewat route terautentikasi.
- **Format buku bisa berubah saat pembinaan.** Jangan mengunci layout di dalam controller — semua urutan kolom diambil dari satu konfigurasi per buku (`config/buku/*.php`) supaya bisa diperbaiki tanpa menyentuh logika.
- **Nomor urut buku** harus stabil: kalau baris dihapus, nomor tidak boleh bolong/berubah retroaktif. Simpan `no_urut_tahun` saat record dibuat.
- **Tanda tangan** tetap manual (cetak → TTD basah). Jangan janjikan TTD digital di Fase 1; kalau nanti perlu, bentuknya scan TTD + QR verifikasi.
- **Internet di kelurahan** tidak selalu bagus → halaman harus ringan (tanpa chart), form tahan gagal submit, dan semua buku bisa di-export supaya ada salinan lokal.

**Tradeoff yang sudah dipilih**

- Blade + AdminLTE (bukan React/Inertia): paling cepat dibangun, paling gampang dirawat kalau Dea/Iwan yang pegang, dan cocok dengan app-app lain.
- Satu tabel `orang` dipakai bersama semua buku (bukan tabel per buku): menghilangkan input ulang, tapi butuh disiplin validasi & dedupe saat import (kunci: nama + tanggal lahir + RT).

**Pertanyaan terbuka (butuh jawaban Iwan)**

1. Hosting & domain: taruh di dea-geekom (Cloudflare Tunnel) atau VPS? Siapa yang akses dari luar rumah?
2. Siapa yang jadi operator harian — sekretaris kelurahan sendiri, atau dibantu kader RT?
3. Apakah TP PKK Kota/Kecamatan punya aplikasi/format resmi (di file ada catatan "Studi Tiru Griya Digitalisasi") yang harus diikuti?
4. Perlu fitur absen mandiri kader lewat HP (QR/link) di Fase 1, atau cukup operator yang mencentang?
5. Data 2022–2025 (program kerja, agenda surat lama) diimport juga atau cukup yang 2026?
